# Before vs With LOOP

## Scenario

> *“I want teammates for a hackathon this weekend — frontend + someone who can ship backend. I’m tired of posting in five chats and getting silence.”*

This is a common developer community pattern: the need is real, but the **path from intent → match → collaboration** is unclear.

---

## Before LOOP

| Step | User experience | System gap |
|------|-----------------|------------|
| 1 | Posts the same ask in Discord / WhatsApp / Twitter | Fragmented channels |
| 2 | Profiles are thin or missing | Hard to trust fit |
| 3 | Interest arrives as vague DMs | No structured request |
| 4 | Team size and roles stay informal | Capacity chaos |
| 5 | Chat never starts, or starts without context | Match ≠ collaboration |

**Result:** Time lost, weak teams, and abandoned hackathon energy.

---

## With LOOP

| Step | System action | User benefit |
|------|---------------|--------------|
| 1 | User publishes a structured hackathon team card | Clear recruiting signal |
| 2 | Peers filter discovery by “need teammates” | Intent-aligned browsing |
| 3 | **Request to Join** with confirm flow | Explicit intent, less spam |
| 4 | Owner accepts → membership + capacity check | Safe team growth |
| 5 | Partnership / team chat opens | Collaboration starts with context |

**Result:** Faster clarity, fairer recruiting, and a path from “looking” to “building.”

---

## Transformation Summary

```text
Scattered posts        →  Intent-based discovery
Vague DMs              →  Structured requests
Informal team size     →  Capacity-aware membership
Match and disappear    →  Chat + active team badge
Silent community pulse →  Live Loop signals
```

> *“LOOP doesn’t invent community — it gives community a product shape.”*
