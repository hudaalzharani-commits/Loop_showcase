# Glossary

Shared vocabulary for the LOOP product case study.

| Term | Meaning |
|------|---------|
| **LOOP** | Mobile-first community platform for developers to learn, build, and grow together |
| **Learner / Builder / Mentor** | Product roles expressing how a user primarily shows up in the community |
| **Looking for** | Declared intent (e.g. study partner, build partner, hackathon team) used in discovery |
| **Live Loop** | Home pulse of community activity (online learners, rooms, projects, teammate demand) |
| **Discovery** | Intent-filtered browsing of people and opportunities |
| **Study room / group** | Shared space for presence and accountability while learning |
| **Hackathon team card** | Structured recruiting post (roles, size, availability, commitment, idea, ON/OFF) |
| **Request to Join** | Explicit join ask with confirmation UI and persisted request record |
| **Request lifecycle** | `pending` → `accepted` \| `declined` \| `cancelled` \| `expired` |
| **Capacity** | Team size limit that gates further accepts when full |
| **Recruiting closed** | Team no longer accepting join requests |
| **Partnership chat** | Conversation opened when a collaboration request is accepted |
| **Active Hackathon Team badge** | Profile signal that the user is currently on a team |
| **Builder portfolio** | Project / GitHub-linked identity surface for credibility |
| **Platform role** | Ops role (`moderator` / `admin` / `founder`) separate from product role |
| **Founder Direct** | In-app channel to talk to the founder (not email) |
| **Support ticket** | In-app help request tracked for staff |

For architecture terms, see [System Architecture Overview](../architecture/system-architecture-overview.md).
